## 2. 第一性原理與設計取捨

簡潔不是刪除能力，而是減少同時需要理解的資訊。完整不是工具數量多，而是輸入、結果、比較、錯誤與保存都能走完。

| 使用者真正需要 | 設計原則 | 不採用的做法 |
| --- | --- | --- |
| 快速找到適用工具 | 用需求問句、工具名稱與同義詞導引 | 大型自動輪播、空的工具分類 |
| 以少量資料開始 | 基本／進階欄位分組，公開目前假設 | 隱藏假設卻呈現像確定答案的數字 |
| 知道答案代表什麼 | 先呈現三項重點，再提供明細 | 所有結果、備註與操作同等醒目 |
| 比較選項的代價 | 共同基準、差異標記、費用與風險並列 | 只因月付較低就標成最佳方案 |
| 保有資料控制權 | 預設不保存，主動選擇本機檔案／儲存 | 登入牆、預設記住、帶金額的分享網址 |
| 相信網站與作者 | 模型、限制、利益揭露與實測證據 | 不實安全承諾、虛構優惠與功能 |

## 4. 資訊架構與首頁

既有路由保持有效，不因改名破壞深層網址。導覽保留四項：首頁、工具大全、推薦優惠、關於 Larry。計算方法／隱私／原始碼放頁尾與各工具的相關位置。

首頁區塊依序為：

1. 簡短標題「把假設算清楚，再做決定」、一句「免登入，財金試算在你的瀏覽器完成」、工具搜尋。
2. 目的入口：「買房月付多少？」→ 房貸；「借款成本差多少？」→ 信貸；「質押跌多少要注意？」→ 質押；「還要存多少才能退休？」→ 退休；「配置改變會有什麼影響？」→ 投資組合。
3. 五項工具卡：名稱、解決的問題、主要輸出與「開始試算」。第一版只有五項，不顯示假的人氣／使用次數／排行。
4. 一個虛構案例與三步使用說明；作者短介及作品原始碼入口。

首頁與工具總覽共用同一份工具資料，避免名稱、描述、搜尋與網址各自維護。首頁搜尋直接篩選卡片；工具總覽額外提供「全部／買房與借貸／投資與退休」按鈕。標明結果筆數，提供清除與零結果狀態；搜尋字串保留在當頁記憶體，不加入網址或外部請求。

最小同義詞：房貸／購屋／頭期款／月付；信貸／借款／開辦費；質押／維持率／追繳；退休／FIRE／財務自由；配置／組合／再平衡。空白顯示全部，前後空白忽略，英文不分大小寫，輸入一律當文字處理。查詢以工具資料明確定義的詞比對，不能用無關結果填滿畫面。

## 5. 視覺與響應式版型

保留青綠主色、近白底、深灰文字；每頁只有一項主要操作使用實心主色。同一工具不再以大量邊框卡片包住每段說明。系統字型、內文至少 16px、行高約 1.5–1.7；數字採等寬數字，幣別與單位不可省略。間距採 4／8／12／16／24／32／48px，圓角統一 8–12px；狀態以圖示加文字，不只靠紅綠。

- >=1280 CSS px：內容最大寬約 1440px，推薦欄 240–260px，欄距 24px；工具主區可分輸入與結果，輸入不小於約 360px、結果不小於約 400px。放不下即切換堆疊，不擠壓欄位。
- 1100–1279px：主區輸入與結果上下堆疊、右側保留推薦欄。
- <1100px：單欄；推薦區放工具主要結果與比較之後，可展開；每頁仍保留入口。表格只能在自身容器內水平捲動。
- 360×800 與 390×844、100% 字級：工具頁首屏必須可見標題、簡短用途及第一個基本輸入；不是要求整份表單塞進首屏。
- 1440×900、100% 字級：可見基本輸入與至少三項範例結果的標籤／數值。頁面須明確標為虛構範例，不能把預設當作訪客資料。
- 不設自動輪播、滿版介紹、浮動廣告或遮擋焦點的固定操作列。首版不追求所有區塊皆固定；長側欄必須自然可達。

## 6. 共用工具流程

順序：標題與一句用途 → 基本設定及進階入口 → 核心結果 → 情境比較 → 圖表／明細 → 完整方法／限制 → 儲存與管理。桌機可並排，DOM 閱讀順序仍為輸入後結果。

採有效輸入自動重算，約 250ms 防抖，正常範圍最後一次輸入後 500ms 內更新（指定驗收裝置記錄環境）；主要操作改「查看結果」，負責移動至結果標題，不製造另一套計算模式。輸入期間不奪走焦點、不因加逗號重建整份表單；結果區不每次重算都以 live region 宣讀全部內容。錯誤摘要於提交／離開欄位時提示，修正後立即解除。

無效輸入時，原結果必須標成「輸入待修正，以下結果已失效」並禁止匯出結果 CSV；保留原輸入供修正。不可顯示無警示的舊答案。重設只影響目前工具，執行後提供短暫復原；若技術上無法可靠復原，執行前顯示清楚確認，不能無提示清掉多情境。

進階設定折疊不清空值；按鈕旁顯示摘要（如「通膨 3%、退休後報酬 5%」），有錯誤時自動展開並提供焦點連結。每個隱藏預設仍出現在結果的「本次假設」摘要。完整方法預設折疊，重要限制摘要始終可見。

「儲存與管理」使用簡單 details／summary 收合區：範例、重設、JSON 匯入／匯出、複製工具網址、選擇性記住／刪除本機設定；不得把它們全部放在輸入之前。下載結果 CSV 直接放於明細旁。複製成功／失敗提供文字回饋與手動備援。

## 8. 情境比較契約

情境名稱使用「A／B／C」或自訂文字，實際利率／報酬以獨立徽章顯示；不可把寫死的 5% 留在修改後名稱。新建比較由「複製目前情境」產生，深複製所有輸入，修改 B 不影響 A。

退休保留三情境容量與 5%／7%／10% 範例組合，但初次頁面使用一個清楚標示的範例 A；「載入三組報酬範例」為明確操作。已存在或匯入的三情境不應被刪除。此處是對原三情境預設呈現的變更，公式不變。

比較表列出結果與全部不同的輸入欄位；年齡、本金、月投入、月支出不同時醒目提示「基本條件不同」。提供「以 A 的基本條件套用至其他情境」，操作前列出會覆寫的欄位並確認；保留各情境名稱及利率／報酬等比較變數。各工具欄位集合須明確定義並測試，不使用任意物件拷貝猜測。

退休同步：現齡、退休／終止年齡、淨資產、月投入／支出、收入與起始年齡、通膨；不覆寫退休前後報酬。房貸同步本金來源、房價／頭期款或本金、收入及其他債務；保留各方案利率／期數／攤還／寬限／費用。信貸同步本金；保留利率、期數、費用。投資組合沿用獨立組合比較，完整顯示差異，不增加模糊的同步按鈕。質押只比較壓力列，不新增跨方案同步功能。

JSON 保持原 schemaVersion/toolId/inputs 契約，新增純 UI 狀態不寫入財務輸入；舊檔案仍可匯入，未知欄位依既有規則驗證，不悄悄遺失情境。任何格式變更另訂遷移規格。

### 易用性驗證

由未參與實作的人操作虛構資料：找到房貸、比較兩個方案、找出寬限期後月付、調整退休月支、匯出並還原設定。初期探索目標為 3 人各完成 5 任務，至少 12/15 次不需口頭協助，且沒有把範例當本人資料、把估算當保證或搞錯方案的嚴重誤解。記錄實際時間、卡點、提示次數及改進；這是小樣本改善依據，不代表統計顯著。

若無法取得受測者，記為「未執行」，agent 瀏覽器驗證仍需完成，但不能宣稱人類易用性目標已達成；可提交候選版本供擁有者測試，尚不能標記「完整易用性驗收通過」。
